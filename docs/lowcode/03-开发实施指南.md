# 低代码开发实施指南

面向研发：如何在现有仓库上 **加业务、加页面、加菜单**，以及后期如何演进到 **自建应用 / 扩展包**。

---

## 1. 今天就能用的三条路径

### 路径 A：代码生成 + ZIP（标准 CRUD）

**适用**：新表、标准增删改查、要交付 Java/Vue 源码。

1. 管理端 → 代码生成 → 导入表 → 编辑 `moduleName`、`businessName`、`packageName`  
2. 下载 ZIP，按 [02-当前能力与发布菜单.md](./02-当前能力与发布菜单.md) 合并  
3. 启动 API + 前端，验证接口与页面  
4. 「发布菜单」或调 `POST /generator/table/publishMenus`  
5. 重新登录  

**后端包路径**（默认）：

```
com.geekplus.webapp.{moduleName}.controller
com.geekplus.webapp.{moduleName}.service
...
```

**权限前缀**：`{moduleName}:{businessName}`，与 `@RequiresPermissions`、菜单 `perms` 一致。

### 路径 B：表单设计器导出单页

**适用**：复杂表单布局、不需要完整 CRUD 生成。

| 步骤 | 位置 |
|------|------|
| 设计 | `src/views/admin/tool/build/index.vue` |
| 导出 | `utils/generator/html.js`、`js.js` |
| 落地 | 手工放入 `views/admin/...` 并配菜单 |

后期：导出结果改为 `lc_page.schemaJson`，由运行时壳渲染（阶段 1）。

### 路径 C：完全手写模块

**适用**：强交互、非表格型页面（PPT、简历、骨架工作室）。

1. 在 `src/views/admin/{module}/` 新建 Vue  
2. 后端 `com.geekplus.webapp.{module}` 写 Controller/Service  
3. `sys_menu` 手工维护或复用发布菜单逻辑（改 `component` 指向你的路径）

## 2. 后端：新增业务模块

### 2.1 目录约定

```
GeekPlus-Blog-API/src/main/java/com/geekplus/webapp/
  {moduleName}/
    controller/{Entity}Controller.java
    service/{Entity}Service.java
    service/impl/{Entity}ServiceImpl.java
    entity/{Entity}.java
    mapper/{Entity}Mapper.java
resources/mybatis/{moduleName}/{Entity}Mapper.xml
```

### 2.2 权限

Controller 方法使用：

```java
@RequiresPermissions("function:book:list")
```

菜单按钮 `perms` 与之一一对应（发布菜单 API 已按 `sql.ftl` 生成五类按钮）。

### 2.3 操作日志

```java
@Log(title = "图书管理", businessType = BusinessType.INSERT)
```

### 2.4 数据权限（可选）

见 `GeekPlus-Blog-API/docs/07-数据权限使用说明.md`，Service 层加 `@DataScope`。

## 3. 前端：列表与表单页

### 3.1 代码生成页（当前）

生成器产出典型结构：

- `index.vue`：`el-table` + 查询表单 + 弹窗表单  
- `{business}.js`：`request` 封装 CRUD URL  

动态路由加载：

```140:140:src/store/modules/permission.js
      component: item.component ? (resolve) => require([`@/views/admin/${item.component}`], resolve) : Layout,
```

**注意**：`component` 需带 `.vue` 后缀（与 `tool/generator/index.vue` 一致）。

### 3.2 手写列表页 checklist

- [ ] API 文件 `src/api/{module}/{business}.js`  
- [ ] 页面 `src/views/admin/{module}/{business}/index.vue`  
- [ ] 按钮 `v-hasPermi` 或项目内权限指令与 `perms` 对齐  
- [ ] 菜单 `component`、`path`、`perms`  
- [ ] 路由 `name` 由 `permission.js` 根据 `path` 生成，避免中文 path  

### 3.3 与表单设计器字段对齐

`utils/generator/config.js` 定义字段类型；`build` 页拖拽后可通过 `html.js` 生成 `el-form-item`。  

后期统一 Schema 字段：

```json
{ "field": "title", "label": "标题", "component": "input", "required": true }
```

## 4. 菜单与权限

### 4.1 手工添加

`系统管理 → 菜单`，或 API `POST /sys/menu/add`。

### 4.2 代码生成发布（推荐）

`POST /generator/table/publishMenus` — 见 [02-当前能力与发布菜单.md](./02-当前能力与发布菜单.md)。

### 4.3 角色授权

发布对话框可选角色；或 `POST /sys/roleMenu/batchAdd`。

### 4.4 刷新权限

菜单变更后：`rbacCacheService` 已 evict；用户需 **重新登录** 或调用现有刷新权限流程（`permission.js` / `user/refreshAuth`）。

## 5. 后期：自建应用（lc_app）

### 5.1 建议表结构（阶段 1）

```sql
-- 应用
CREATE TABLE lc_app (
  app_id        VARCHAR(32) PRIMARY KEY,
  app_name      VARCHAR(64) NOT NULL,
  icon          VARCHAR(64),
  package_prefix VARCHAR(128),  -- 权限与 API 前缀，如 function:book
  entry_type    VARCHAR(16),    -- codegen | schema | custom
  status        TINYINT DEFAULT 0,
  tenant_id     BIGINT DEFAULT 0,
  remark        TEXT,
  create_by     VARCHAR(64),
  create_time   DATETIME
);

-- 页面
CREATE TABLE lc_page (
  page_id       VARCHAR(32) PRIMARY KEY,
  app_id        VARCHAR(32) NOT NULL,
  page_type     VARCHAR(16),    -- list | form | dashboard | custom
  title         VARCHAR(64),
  schema_json   JSON,
  route_path    VARCHAR(128),
  sort          INT DEFAULT 0
);
```

### 5.2 安装应用 = 三件事

1. 写入 `lc_app` + `lc_page`（及可选 `lc_entity`）  
2. 调用菜单发布（`component` 指向运行时壳 + `meta.pageId`）  
3. 写 `sys_role_menu`（可复用现有 batchAdd）  

**幂等**：`app_id` 唯一；菜单可用 `component=lowcode/AppRuntime.vue` + `remark` 存 `appId`，或 `perms` 前缀唯一。

### 5.3 运行时壳（待开发）

建议新建：

```
src/views/admin/lowcode/
  CrudListRuntime.vue    # 读 schemaJson 渲染表格
  CrudFormRuntime.vue    # 读 schemaJson 渲染表单
  AppRuntime.vue         # 根据 meta 分发 list/form/custom
```

API：

```
GET  /lc/page/{pageId}/schema
POST /lc/runtime/{appId}/{entity}/list   # 或复用已生成 Controller
```

## 6. 后期：扩展包（自定义开发包）

### 6.1 前端扩展包

```
packages/
  lc-core/           # Schema 类型、运行时注册表
  lc-widgets/        # 额外组件：富文本、地图…
  apps/
    my-crm/          # 自建应用纯自定义页面
      src/pages/...
      package.json
```

**注册表**（示意）：

```javascript
// packages/lc-core/registry.js
export const widgetRegistry = new Map()
export function registerWidget(type, component, meta) {
  widgetRegistry.set(type, { component, meta })
}
```

设计器与运行时共用 `registry`，避免双份配置。

### 6.2 后端扩展包

```java
// 扩展点接口
public interface LcValidator {
    String entity();
    void beforeSave(Map<String,Object> row);
}

// 应用 jar 或同仓 apps/crm 模块
@LcExtension(appId = "crm")
public class CrmLeadValidator implements LcValidator { ... }
```

启动时扫描 `lc_package` 表或 `spring.factories`，注册到 `LcExtensionRegistry`。

### 6.3 与代码生成共存

| entry_type | 行为 |
|------------|------|
| `codegen` | 走 gen_table + ZIP，菜单指向真实 Vue |
| `schema` | 菜单指向 `AppRuntime`，页面在 DB |
| `custom` | 菜单指向 `apps/{app}/pages/...` |
