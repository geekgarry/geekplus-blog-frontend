# 用户管理 · 动态条件查询

与 Plus Admin 对齐：列表筛选项为「字段 + 运算符 + 值」，并按 `valueType` 适配控件。

## 方案 A（列表请求）

`POST /sys/user/list`：

| 位置 | 内容 |
|------|------|
| query | `pageNum` / `pageSize` / **`conditionsJson`（兜底）** |
| body | `conditionsJson`、部门等（与扁平字段互斥） |
| header | 可选 `X-GP-Conditions-Json` |

**重要**：开发代理默认指向 `mkapi`。本地改过的 Blog-API **必须部署到 mkapi**，或：

```bash
VUE_APP_PROXY_TARGET=http://127.0.0.1:9002 npm run serve
```

否则会出现「前端填了条件，SQL 却是 `SELECT … FROM sys_user` 无 WHERE」。

## 互斥约定

| 场景 | 请求参数 | SQL |
|------|----------|-----|
| 有有效动态条件 | **只传** `conditionsJson` | 只走 `DynamicWhere`（`params.dq`） |
| 无动态条件 | 可不传筛选项；旧调用方可只传扁平字段 | 只走扁平 `like` / `=` |

## 字段类型

- 组件：`DynamicQueryForm` + `queryFieldTypes.js`
- 已配置字段：用户名/昵称/手机/邮箱、状态、用户类型、性别、登录 IP、**登录/创建/更新时间**（datetime）、创建者、备注
- `isNull` / `isNotNull` → 值控件禁用；时间字段用日期时间选择器，可用大于/小于等比较

后端白名单：`SysUser.dynamicQueryColumns`（须含 `loginTime`/`createTime`/`updateTime` 等，部署后生效）。

## 排查：前端有 conditionsJson 但 SQL 无 WHERE

1. Network 已带 `conditionsJson`（你已确认）→ 前端 OK  
2. 若 SQL 仍是 `SELECT … FROM sys_user` 无条件 → **后端未写入 `params.dq` 或 Mapper 未拼 DynamicWhere**（常见：仍代理到未部署的 mkapi）  
3. 本机验证：
   - 启动 Blog-API（dev 端口 **9002**）
   - `.env.development` 已设 `VUE_APP_PROXY_TARGET=http://127.0.0.1:9002`，**重启** `npm run serve`
   - 日志应出现：`dynamic query ready: … dqSize=1 … username.eq=geekplus`
   - SQL 应含 `AND username = ?`
