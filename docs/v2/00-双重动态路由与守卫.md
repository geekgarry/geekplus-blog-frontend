# 做 Vue 博客最容易翻车的地方：前台栏目 + 后台权限，两套动态路由怎么和平共处

> 系列第 0 篇
> 关键词：`addRoute`、路由守卫、直链白屏、navMenu、permission、白名单  
> 对应源码：`src/permission.js`、`src/store/modules/navMenu.js`、`src/store/modules/permission.js`、`src/store/modules/user.js`、`src/router/index.js`

---

## 先说人话：为什么博客站要搞「两套菜单」

做企业中后台的同学，一般只熟悉一套动态路由：

> 登录 → 拉角色菜单 → `router.addRoute` → 侧边栏渲染。

博客站多了一层现实：

1. **路人也能逛**。栏目、文章、搜索不能要求先登录。  
2. **栏目是运营配的**。今天叫「科技社」，明天改名改 path，前端不可能写死在 `constantRoutes` 里。  
3. **后台还是那套权限菜单**。写文章、管评论、改站点信息，必须按权限动态挂。

于是天然出现两套数据源：

| | 前台博客菜单 | 后台管理菜单 |
|--|-------------|-------------|
| 谁用 | 游客 / 登录用户逛站 | 管理员干活 |
| 数据从哪来 | 栏目树接口（如 `listSubParentCategory`） | 用户菜单树（如 `getMenuTree`） |
| 存哪 | Vuex `navMenu` | Vuex `user.menus` + `permission` |
| 挂到哪 | 父路由 `webApp`（BlogShell） | 独立 admin 路由树 / Layout |
| 要不要登录 | **不要** | **要** |
| 失败了怎么办 | 静态页（首页、关于）仍能开 | 清 token、回登录页 |

很多教程只讲后台那一套。博客把两套塞进同一个 `permission.js` 守卫里，一不小心就会：

- 直开栏目链接白屏  
- 404 抢先匹配，栏目永远进不去  
- 前台菜单和后台菜单互相污染  
- 并发进站重复 `addRoute`，HMR 后再挂一遍炸路由表  

下面按「我们怎么想清楚 → 怎么实现 → 踩过什么坑 → 怎么把体验做顺」讲一遍。你可以当改造清单用。

## 一、先画一张「进站时发生了什么」

打开任意 URL，全局守卫大致走这条流水线：

```text
浏览器输入 URL
    │
    ▼
router.beforeEach
    │
    ├─① initPublicRoutes()     ← 人人都要跑：挂前台栏目
    │     ├─ 已注册？直接放行
    │     ├─ 有 session 缓存？先用缓存生成路由
    │     ├─ 否则打栏目接口
    │     ├─ addRoute('webApp', …)
    │     ├─ 最后再挂 * → /404（很重要）
    │     └─ 若本轮刚挂上 → needRematch=true
    │
    ├─② 若 needRematch → next({ path: fullPath, replace:true }) 结束本轮
    │                     （下一轮守卫再进来时，路由已经在表里了）
    │
    ├─③ 有 Token？
    │     ├─ 正在去登录页 → 踢去 /admin
    │     ├─ user.menus 还是空 → 拉后台菜单 → addRoute → 再 replace 一次
    │     └─ 已有 menus → next()
    │
    └─④ 无 Token？
          ├─ 白名单前缀 → next()
          ├─ /admin* → 提示登录，带 redirect
          └─ 其它前台路径 → next()（交给匹配结果，匹配不到后面有 404）
```

记住一句话就够用了：

> **前台路由解决「站能不能逛」；后台路由解决「你能不能管」。守卫里先搞定逛，再按需搞定管。**

## 二、静态路由只放「骨架」，动态路由才放「皮肉」

### 2.1 静态里该有什么

`src/router/index.js` 的 `constantRoutes` 大致分三拨：

1. **管理端壳子**：`/login`、`/admin`（带 Layout）、若干 hidden 工具页  
2. **博客壳子**：`/` → `BlogShell`，children 是首页、搜索、文章、关于等**固定页**  
3. **独立页**：登录页 `/user`、聊天 `/chat` 等

**不要**把运营栏目写死在静态表。栏目一改，你就要发版。

### 2.2 动态里各管各的

**前台（`navMenu`）：**

```js
// 数据：栏目树 → 标准化 → 可 addRoute 的路由对象
listSubParentCategory()
  → getMenuList()        // 叶子不要带 children:[]
  → generateRoutes()     // setChild 拼 meta / component
  → addChildRoute('webApp', item)
```

**后台（`user` + `permission`）：**

```js
getMenuTree()
  → commit SET_MENUS / SET_PERMISSIONS
  → generaMenu() + filterAsyncRoutes(dynamicRoutes)
  → router.addRoute(item)   // 通常是完整带 Layout 的树
```

两套 store 模块**刻意分开命名**：`navMenu` vs `user`/`permission`。别图省事塞一个 `menus` 数组里用 `type` 字段区分——半年后你一定分不清。

## 三、实现步骤（照着做能跑通）

### 步骤 1：约定父路由名字

前台动态子路由统一挂到 `name: 'webApp'` 的父级下（现在父组件是 `BlogShell`）。  
后台动态路由一般是顶层 `addRoute`，自己带 `Layout`。

```js
// 前台
router.addRoute('webApp', childRoute)

// 后台
router.addRoute(adminRouteWithLayout)
```

### 步骤 2：写 `addChildRoute`，带去重

HMR、守卫重入、预取和正式导航重叠时，很容易加两次：

```js
function addChildRoute(parent, route) {
  if (!route || route.path == null) return
  const exists = router.getRoutes().some(
    (r) => r && r.path === route.path && r.name === route.name
  )
  if (!exists) {
    router.addRoute(parent, route)
  }
}
```

### 步骤 3：前台菜单拉取要「可缓存、可合并并发」

```js
// navMenu/getMenu 思路
let menuLoadingPromise = null

getMenu({ commit }) {
  if (menuLoadingPromise) return menuLoadingPromise

  menuLoadingPromise = new Promise((resolve, reject) => {
    let usedCache = false
    // 1) sessionStorage 命中 → 立刻 resolve，页面能先匹配路由
    // 2) 同时仍请求接口，静默刷新缓存
    // 3) 未命中缓存才等接口 resolve / reject
    // finally 清空 menuLoadingPromise
  })
  return menuLoadingPromise
}
```

体验上的好处：用户刷新栏目页时，**不需要每次干等接口**才开始匹配路由。

### 步骤 4：叶子节点别写空 `children: []`

这是血泪注释写进代码里的：

```js
// 空数组在 JS 里是 truthy
// 布局里 v-if="item.children" 会当成「有子菜单」
// 然后去读 children[0].path → 炸
```

叶子只返回字段，不要 `children` 键；有孩子再递归。

### 步骤 5：组件懒加载要「扫得准」

前台：

```js
export const loadView = (view) => () =>
  import(
    /* webpackChunkName: "web-view-[request]" */
    /* webpackExclude: /[\\/]admin[\\/]/ */
    `@/views/${view}`
  )
```

`webpackExclude` 挡住 admin，避免博客包被管理端拖肥。

后台 historically 用 `require([\`@/views/admin/${component}\`])`，注释里提醒过 `import()` 异步拼路径的坑——按你们构建环境选稳定方案，但**前台后台加载器一定要分开**，别共用一个扫全 `views` 的 context。

### 步骤 6：守卫里「先公共，后权限」

完整节奏见文首流程图。对应代码骨架：

```js
router.beforeEach(async (to, from, next) => {
  NProgress.start()
  const hasToken = getToken()

  const { ok, needRematch } = await initPublicRoutes()
  if (!ok) {
    Message.error('加载站点菜单失败，请刷新重试')
    next('/404')
    return
  }
  if (needRematch) {
    // 只用 fullPath，不要展开整个 to
    next({ path: to.fullPath, replace: true })
    return
  }

  if (hasToken) {
    if (isGoingToLogin(to)) {
      next('/admin')
      return
    }
    if (store.state.user.menus.length === 0) {
      try {
        const routes = await store.dispatch('user/getMenu')
        const addRoutes = await store.dispatch('generateRoutes', { routes })
        addRoutes.forEach((item) => router.addRoute(item))
        next({ path: to.fullPath, replace: true })
      } catch (e) {
        await store.dispatch('user/logout')
        next(`/login?redirect=${to.path}`)
      }
      return
    }
    next()
  } else {
    if (inWhiteList(to.path)) next()
    else if (to.path.startsWith('/admin')) {
      Message.warning('您尚未登录，请先登录！')
      next(`/login?redirect=${to.path}`)
    } else next() // 前台动态路径已在 initPublicRoutes 挂好
  }
})
```

### 步骤 7：404 挂载时机

```js
// 必须在全部动态栏目 addRoute 之后
router.addRoute({ path: '*', redirect: '/404', name: '404', hidden: true })
```

如果 `*` 先挂，栏目 path 全被吞掉，你会以为「接口没返回」，其实是路由表顺序错了。

### 步骤 8：模块加载就预取前台菜单

```js
const publicMenuPrefetch = store.dispatch('navMenu/getMenu').catch(() => null)
```

和首屏 JS 解析并行，直链栏目时守卫里经常已经能吃到预取结果。

## 四、核心技术点深挖

### 4.1 为什么 `addRoute` 之后必须 `replace` 再进一次？

Vue Router 在 `beforeEach` 触发时，**已经根据「当时的路由表」算好了 `to.matched`**。  
你在守卫里现加路由，**不会自动改写这一次的 matched**。

所以：

| 动作 | 结果 |
|------|------|
| 只 `next()` | 继续用空 matched → `<router-view>` 没东西 → **白屏** |
| `next({ path: to.fullPath, replace: true })` | 取消本次，用新表重新匹配 → 正常渲染 |

后台第一次拉菜单同理，也要 replace 一次。

### 4.2 为什么不要 `next({ ...to })`？

`to` 是路由记录对象，展开可能带上 `name: null`、`matched`、内部字段。  
vue-router 再解析时，偶发：

```text
Cannot read properties of undefined (reading 'path')
```

**只传你真正需要的定位信息**：`path` / `fullPath` / 必要的 `query`、`hash`。我们统一用：

```js
next({ path: to.fullPath, replace: true })
```

### 4.3 `routesRegistered` 标记干什么用？

会话内守卫会跑很多次（每次跳转）。没有标记就会：

- 反复打栏目接口  
- 或反复 `addRoute`（即使有 path 去重也浪费）

```js
if (store.state.navMenu.routesRegistered) {
  return { ok: true, needRematch: false }
}
```

注意：标记表示「**已经尝试注册过**」，菜单为空时也要置 true，否则无栏目的站点会每次导航都卡住重试。

### 4.4 白名单怎么设计才不堵前台

白名单解决的是：**没登录时，哪些路径明确放行**。  
前台动态栏目 path 无穷无尽，不可能全写进数组。所以策略是：

1. 静态常见页写进 whiteList（文章、搜索、关于……）  
2. `/admin` 单独拦  
3. **其它前台路径默认 `next()`**，因为栏目已在步骤 ① 挂上；匹配不到再靠 404

不要学某些后台模板「不在白名单就全部踢登录」——博客会被自己噎死。

### 4.5 两套菜单的「边界卫生」

| 建议 | 原因 |
|------|------|
| store 分模块 | 避免 logout 清错前台栏目 |
| `type: 'navMenu' / 'admin'` | 顶栏过滤、面包屑好辨认 |
| 后台 Layout 异步 import | 博客首屏不背管理端包 |
| 登出 `resetRouter` + 清 `user.menus` | 换账号不会串权限；前台 `routesRegistered` 是否重置看产品（同标签页一般保留栏目） |

## 五、体验优化清单（可以直接当验收）

### 5.1 直链栏目 < 1 次闪白

- [x] 预取 + session 缓存  
- [x] needRematch replace  
- [x] 404 后置  

手动测：复制一个栏目 URL，新隐身窗口打开，应直接出列表，而不是空白再跳。

### 5.2 弱网 / 接口挂了，站还能打开

菜单接口失败时：

- 前台：静态路由仍在，首页、关于能进；提示「菜单加载失败」而不是整站死循环  
- 后台：登出回登录，别让半残权限挂在内存里  

### 5.3 登录后进后台不二次手点

有 token 还访问 `/login` → 直接 `/admin`。  
未登录撞 `/admin/xxx` → `/login?redirect=...`，登录完能回到原页（redirect 逻辑在登录页消费）。

### 5.4 进度条别假死

`NProgress.start()` 成对 `done()`：  
在 `needRematch` 提前 `return` 的分支，要么不 start，要么 afterEach 统一 done（我们用 afterEach）。  
失败分支记得手动 `NProgress.done()`，避免顶栏细条永远卡着。

### 5.5 开发体验：HMR 不炸路由

`addChildRoute` 按 path+name 去重；热更新重复进守卫时不会叠十层同名路由。

## 六、对照表：常见故障 → 怎么查

| 现象 | 优先怀疑 | 排查 |
|------|----------|------|
| 栏目直链白屏 | 没 rematch | 看守卫是否 `needRematch` 后 replace |
| 所有未知路径都像栏目 | `*` 挂太早 | 确认 404 在动态 add 之后 |
| 菜单有项点进去 404 | path 拼接 / component 路径错 | 对一下后台配的 `component` 与 `views` 目录 |
| 子菜单箭头有、点开空 | 叶子带了 `children:[]` | 清理空数组 |
| 博客包体积暴涨 | loadView 扫到 admin | webpackExclude / 分目录加载 |
| 换账号权限还在 | 没 resetRouter | logout 清 menus + matcher |
| 并发 401 狂弹窗 | 请求层问题 | 见系列第 3 篇；与路由无关但常一起改 |

## 七、一段「最小可讲清楚」的 initPublicRoutes

```js
async function initPublicRoutes() {
  if (store.state.navMenu.routesRegistered) {
    return { ok: true, needRematch: false }
  }
  try {
    let routes = store.state.navMenu.addMenuRoutes
    if (!routes || routes.length === 0) {
      routes = (await publicMenuPrefetch) || (await store.dispatch('navMenu/getMenu'))
    }
    if (!routes || routes.length === 0) {
      store.commit('navMenu/SET_ROUTES_REGISTERED', true)
      return { ok: true, needRematch: false }
    }

    const accessRoutes = await store.dispatch('navMenu/generateRoutes', { routes })
    accessRoutes.forEach((item) => addChildRoute('webApp', item))

    if (!router.getRoutes().some((r) => r.path === '*' || r.name === '404')) {
      router.addRoute({
        path: '*',
        redirect: '/404',
        type: 'error',
        hidden: true,
        name: '404'
      })
    }

    store.commit('navMenu/SET_ROUTES_REGISTERED', true)
    return { ok: true, needRematch: true }
  } catch (e) {
    console.error(e)
    return { ok: false, needRematch: false }
  }
}
```

把它和后台 `user.menus.length === 0` 分支放在一起读，双重动态路由的全貌就齐了。

## 八、和后面几篇的关系

- **第 1 篇 BlogShell**：动态栏目挂在哪个父组件里渲染（顶栏壳还是侧栏壳）。  
- **第 2 / 6 篇**：挂上的菜单怎么在 UI 里展示、怎么折叠。

路由是地基；布局和导航是装修。地基不稳，装修再好看也会白屏。

## 九、小结

做 Vue 博客的动态路由，难的不是 `addRoute` API，而是：

1. **两套数据、两套生命周期**（游客栏目 vs 登录权限）要在一个守卫里排好队；  
2. **动态挂载后必须重新匹配**，否则直链白屏；  
3. **404、白名单、缓存、去重、包体积**都是体验细节，但每一个都能让你熬夜。

如果你正在把「若依式后台」改成「可对外的博客」，希望这篇能当你的对照表：先让路人逛得顺，再让管理员管得住。
