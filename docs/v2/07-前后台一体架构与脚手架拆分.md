# 前后台一体架构与脚手架拆分指南

> 面向：要理解本仓库「博客前台 + 管理后台」如何共存，以及**以后如何摘掉博客、只留后台脚手架**的同学。  
> 代码以仓库 `src/` 为准；本文描述边界、依赖方向与拆分步骤。

---

## 1. 一句话定位

本项目是一个 **Vue 2 + Element UI 的单体 SPA**：

| 面 | 谁用 | 壳 | 路由来源 |
|----|------|-----|----------|
| **博客前台** | 游客 / 读者 | `BlogShell`（顶栏或侧栏） | 静态 `blogChildrenRoutes` + 运行时 `navMenu` 栏目 |
| **管理后台** | 登录管理员 | `layout/`（侧栏 + TagsView） | 静态 `/admin` 入口 + 运行时 `user/getMenu` 权限菜单 |

两套动态路由共用一个 `vue-router` 实例、一套 axios（`utils/http`）、一个 Vuex，由 **`src/permission.js`** 做总闸门。

```
浏览器 URL
    │
    ▼
permission.js（beforeEach）
    ├─ ① initPublicRoutes → addRoute('webApp', 栏目…)
    ├─ ②（若后台待加载）拉 user/getMenu → addRoute(管理端…)
    └─ ③ 最后挂 CatchAll404（* → /404）
    │
    ├─ 匹配到 BlogShell 子路由 → 博客页
    └─ 匹配到 Layout 子路由   → 后台页
```

## 2. 目录心智模型（按「能否带走做脚手架」分组）

### 2.1 后台脚手架核心（拆脚手架时优先保留）

```
│   ├── auth.js

```

```
│   （不含 views/admin）
```

- `utils/http/*`：与 Element 解耦的请求工厂，换 UI 适配器即可。

- `views/error/Error404.vue`：通配落点。

## 3. 双重动态路由（务必分清两个 store）

| | 前台栏目 | 后台权限菜单 |
|--|----------|--------------|
| Store | `navMenu` | `user` + `permission` |
| API | 公开菜单接口 | `/sys/user` 鉴权后的菜单树 |
| 挂载点 | `router.addRoute('webApp', child)` | `router.addRoute(route)`（常为 Layout 根） |
| 时机 | 几乎每次进站（游客也要） | 有 Token 且 `user.menus` 为空时 |
| 白屏修复 | `needRematch` → `next({ path: fullPath, replace: true })` | 同上 |

**禁止**把后台菜单写进 `navMenu`，也**禁止**在前台 `initPublicRoutes` 里过早挂 `*` 后再对后台 URL rematch——否则会 404（见第 4 节）。

静态入口（`router/index.js` 节选概念）：

- `webApp` → `BlogShell` + `blogChildrenRoutes`（首页、搜索、文章…）  
- `/admin` → `Layout`（children 多为动态注入）  
- `/login`、`/404`、`/403` 等常驻

## 4. 404 通配与后台直链（当前约定）

### 错误做法（已踩坑）

1. 前台栏目 `addRoute` 完成  
2. 立刻 `addRoute({ path: '*', redirect: '/404' })`  
3. `next({ path: '/admin/system/user', replace: true })`  
4. 此时后台路由还不存在 → 匹配到 `*` → 跳到 `/404`  
5. 后续逻辑面对的是 `/404`，后台菜单加不上或体验错乱  

未登录直接打开 `/admin/...` 时，若先 rematch 进 `*`，也会先看到 404 而不是登录页。

### 正确做法（`permission.js`）

1. 前台注册栏目。  
2. **若** 目标是 `/admin*` 且（未登录 **或** 已登录但 `user.menus` 仍为空）：  
   - **本轮不挂 `*`**  
   - **本轮不对前台做 rematch**  
3. 未登录 → `/login?redirect=...`；已登录 → 拉后台菜单 → `addRoute`（跳过列表里的 `*`）→ **最后** `ensureCatchAll404()` → rematch。  
4. 纯前台导航：前台加完即可挂 `*` 并 rematch。

`ensureCatchAll404` 使用独立 name：`CatchAll404`（不要用静态页的 `name: '404'`）。

## 5. 请求与鉴权分层

```
页面 / API 模块
    → src/utils/request.js          # 本站接线：Token、store、Element Message
        → src/utils/http/createRequest.js   # 可移植核心
            → ui.element.js / ui.console.js
```

- 前台公开接口：可 `headers.isToken = false` 或不带 Token。  
- 后台接口：默认带 Token；401 走统一重新登录。  
- 切标签 / 切 App：GET 默认可 `resumeOnVisible`（见 `docs/v2/03`）。

拆脚手架时：**整夹复制 `utils/http`**，只改 `request.js` 的 baseURL 与 Token 键名即可。

## 6. 后期「只留后台脚手架」怎么拆

目标：得到一个可直接上手的 **Vue2 + Element 中后台模板**（用户/角色/菜单/部门/字典/日志…），不含博客栏目与 BlogShell。

### 6.1 推荐步骤（由易到难）

1. **新建分支 / 新仓库**（如 `geekplus-admin-scaffold`），从本仓库拷贝起步。  
2. **删前台视图与壳**  
   - 删除或移出：`layout/blog/`、`views/article*`、`views/IndexView*`、`store/modules/navMenu.js`、`api/geekplus/`、`assets/css/gp-blog-ui.css`（若后台不用）。  
3. **收窄路由**  
   - `constantRoutes` 只保留：`/login`、`/admin`+Layout、`/404`、`/403`、redirect。  
   - 去掉 `webApp` / `BlogShell` / `blogChildrenRoutes`。  
4. **收窄守卫**（`permission.js`）  
   - 删除 `initPublicRoutes` / `navMenu` 预取。  
   - 保留：Token 校验 → `user/getMenu` → `generateRoutes` → `addAdminRoutes` → `ensureCatchAll404` → rematch。  
5. **白名单**只留 login、register、404、403。  
6. **构建与环境变量**  
   - `VUE_APP_BASE_API` 指向你的管理端 API。  
   - 标题、favicon、README 改成脚手架说明。  
7. **可选**：把博客打成 npm 包或 git submodule，主仓库只引后台（进阶，非必须）。

### 6.2 拆完后的最小进站路径

```
访问 /admin/xxx
  → 无 Token → /login?redirect=…
  → 有 Token → getMenu → addRoute → * 挂末尾 → rematch → 渲染 Layout
```

### 6.3 建议保留的「脚手架卖点」

- 双重不必；**单路动态菜单 + 通配 404 末位挂载** 即可。  
- `utils/http` 可移植请求层。  
- 角色菜单权限 + 数据权限（`data_scope` / `sys_role_dept`）若后端已接好，一并带上。  
- 部门树用户查询（`deptIds` / `includeChildren`）。

### 6.4 不要带到脚手架里的东西

- BlogShell 双布局、栏目 navMenu、文章 Markdown/分享卡、前台广告与轮播业务。  
- 前台专用 CSS Token（除非你想做「同一套视觉」的运营后台）。
