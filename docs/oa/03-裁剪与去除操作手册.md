# 03 · OA 去掉方式手册（逻辑去掉 vs 物理删除）

> 两种**不同**处理方式，按产品需要二选一（或先逻辑、日后物理）。  
> 默认仓库：OA **完整集成、始终可用**；下文是需要「不用 OA」时的操作方法（写在文档里，按需再改代码）。  
> 后端契约：`GeekPlus-Blog-API/docs/19-OA-Flowable.md`。布局：[01](./01-BPMN设计器布局与画布高度.md)。边界清单：[02](./02-模块化拆解与独立定制.md)。

前后端建议**成对**处理。另开 git 分支。

---

## 怎么选

| | **方式 A · 逻辑去掉** | **方式 B · 物理删除** |
|--|----------------------|----------------------|
| 源码 / 依赖 | **保留**在工程里 | **删除**目录与依赖 |
| 启动行为 | 不装配 OA Bean、不启 Flowable、**不建 ACT_*** / 不跑 OA 业务 | 无 OA 类与 Flowable 依赖 |
| 业务使用 | 侧栏无入口、无隐藏路由、调 `/oa/**` 不可用 | 同上，且源码已不在 |
| 再启用 | 改回配置即可 | 从 git 恢复 |
| 适用 | 同一套代码多环境：有的要 OA、有的不要 | 本产品线确定永不做审批 |

# 方式 A · 逻辑去掉（代码保留，启动与业务不用）

目标：工程里**还留着** OA / Flowable / `bpmn-js`，但：

- 前端不进 OA 菜单与隐藏路由、可不加载 `oa-theme`
- 后端不装配 `com.geekplus.oa`、**不启动 Process 引擎、不自动建 ACT_***  
- 不执行 / 不依赖 OA 业务 SQL；已有表可留着不管  
- 业务路径不会走到审批流

> 下列开关**默认未合进主线**；需要逻辑去掉时按本节改一次，用配置翻转。

## A.1 前端

### A.1.1 环境变量

`.env.development` / `.env.production` / `.env.mock`：

```bash
# true=启用 OA；false=逻辑去掉（代码仍在）
VUE_APP_OA_ENABLED=true
```

逻辑去掉时改为 `false`，改完重启 `serve` / 重新 `build`。

### A.1.2 新建 `src/utils/oaModule.js`

```js
/** OA 是否启用；未配置默认 true */
export function isOaEnabled () {
  const v = process.env.VUE_APP_OA_ENABLED
  if (v === undefined || v === null || String(v).trim() === '') return true
  const s = String(v).trim().toLowerCase()
  return s !== 'false' && s !== '0' && s !== 'off' && s !== 'no'
}

/** 去掉 path=oa 或 component 以 oa/ 开头的菜单 */
export function filterOaMenus (menus) {
  if (isOaEnabled() || !Array.isArray(menus)) return menus
  const out = []
  menus.forEach((item) => {
    if (!item) return
    const path = String(item.path || '').replace(/^\/+/, '')
    const comp = String(item.component || '').replace(/^views\/admin\/?/, '')
    if (path === 'oa' || path.startsWith('oa/') || comp === 'oa' || comp.startsWith('oa/')) return
    const next = { ...item }
    if (Array.isArray(item.children) && item.children.length) {
      next.children = filterOaMenus(item.children)
    }
    out.push(next)
  })
  return out
}
```

### A.1.3 `local-routes.js`

```js
import { isOaEnabled } from '@/utils/oaModule'

export const localRoutesByParent = {
  '/tool': [codePlaygroundRoute],
  ...(isOaEnabled()
    ? { '/oa': [oaDesignerEditRoute, oaProcessDetailRoute] }
    : {}),
}
```

### A.1.4 `permission.js` → `generateRoutes`

```js
import { filterOaMenus } from '@/utils/oaModule'
// ...
let permissionRoutes = mergeLocalStaticRoutes(generaMenu(filterOaMenus(routes)))
  .concat(filterAsyncRoutes(dynamicRoutes))
```

### A.1.5 主题：关模块时不加载

1. `admin.scss` **去掉** `@import './oa-theme.css';`  
2. `src/layout/index.vue`：

```js
import { isOaEnabled } from '@/utils/oaModule'
import '@/styles/admin.scss'
if (isOaEnabled()) {
  require('@/styles/oa-theme.css')
}
```

说明：`views/admin/oa` 与 `bpmn-js` **仍保留**；未进页则不会执行业务。直链若未挂路由则进不了页。

### A.1.6（可选加强）库表菜单

即使前端过滤了，也可在 DB / Mock 禁用 OA 菜单（`visible` / 删角色授权），双保险。

## A.2 后端

### A.2.1 配置开关

`application-dev.yml` / `application-prod.yml`：

```yaml
geekplus:
  modules:
    oa: true   # false = 逻辑去掉：不装配 OA、不启 Flowable 建表
```

逻辑去掉时：`oa: false`。

**同时**：该环境**不要执行** `migration_oa_*.sql`（新库不建业务表；旧库可保留表但不挂菜单）。

### A.2.2 不扫描 OA 包（代码仍在磁盘）

新建 `com.geekplus.oa.config.OaModuleExcludeFilter`：实现 `TypeFilter` + `EnvironmentAware`；  
当 `geekplus.modules.oa=false` 时，对类名以 `com.geekplus.oa.` 开头的返回 match（排除装配）。

`GeekPlusBlogApplication` 增加：

```java
@ComponentScan(
  basePackages = "com.geekplus",
  excludeFilters = @ComponentScan.Filter(
    type = FilterType.CUSTOM,
    classes = OaModuleExcludeFilter.class
  )
)
```

`oa=true` / 未配置：过滤器不排除，行为与现在一致。

### A.2.3 不启动 Flowable、不建 ACT_*

新建 `OaModuleEnvironmentPostProcessor`（`EnvironmentPostProcessor`）：  
`geekplus.modules.oa=false` 时，把下列类并入 `spring.autoconfigure.exclude`：

- `org.flowable.spring.boot.ProcessEngineAutoConfiguration`
- `org.flowable.spring.boot.ProcessEngineServicesAutoConfiguration`
- 建议一并：`RestApiAutoConfiguration`、`FlowableJpaAutoConfiguration`、`FlowableSecurityAutoConfiguration`、`EndpointAutoConfiguration`、`org.flowable.spring.boot.actuate.info.FlowableInfoAutoConfiguration`

注册 `src/main/resources/META-INF/spring.factories`：

```properties
org.springframework.boot.env.EnvironmentPostProcessor=\
com.geekplus.oa.config.OaModuleEnvironmentPostProcessor
```

这样：**依赖仍在 pom，但进程内不拉起流程引擎、不会按 `database-schema-update` 建表**。

### A.2.4 Shiro：无 OA 时不挂附件链

`shiroFilterFactoryBean` 将 `OaFileProperties` 改为 `ObjectProvider<OaFileProperties>`；  
仅 `getIfAvailable() != null` 时注册 `oaFile` 与 `/oa/files/**`。  
（OA 包被排除后该 Bean 不存在，自然不挂链。）

### A.2.5 MapperScan 说明

`@MapperScan` 仍可声明 `com.geekplus.oa.**.mapper`；逻辑去掉后无 Controller/Service 引用即可。若希望连 Mapper 都不注册，可把 oa 的 MapperScan 挪到仅在 `oa=true` 时生效的 `@Configuration` 上。

## A.3 逻辑去掉 · 验收

| 项 | 期望 |
|----|------|
| 前端 `VUE_APP_OA_ENABLED=false` | 侧栏无 OA；无设计器/详情隐藏路由；无 `oa-theme` |
| 后端 `geekplus.modules.oa=false` | 无 `/oa/**` Controller；启动日志无 Flowable 建 `ACT_*` |
| 业务 | 其它模块登录、菜单、接口正常 |
| 源码 | `views/admin/oa`、`com.geekplus.oa`、`bpmn-js`、Flowable 依赖**仍在** |
| 再打开 | 两端改回 `true` 并重启 |

# 方式 B · 物理删除（从工程拿掉物料）

目标：目录、依赖、接线都删掉，包体与维护面减小。确定永不做审批时用。  
可先做方式 A 验证无依赖，再执行本节。

## B.1 前端删除

```bash
rm -rf src/views/admin/oa
rm -rf src/api/oa
rm -f src/styles/oa-theme.css
rm -f src/utils/oaBpmnBrand.js
rm -f src/utils/oaModule.js          # 若曾按方式 A 加过
rm -f src/icons/svg/oa.svg src/icons/svg/briefcase.svg   # 可选
# 文档按需：rm -rf docs/oa
```

| 文件 | 操作 |
|------|------|
| `local-routes.js` | 删 OA 两条路由；`localRoutesByParent` 只留 `/tool` |
| `admin.scss` | 删 `@import './oa-theme.css'` |
| `layout/index.vue` | 删 `oa-theme` / `oaModule` 条件引入（若有） |
| `permission.js` | 删 `filterOaMenus`（若有） |
| `.env.*` | 删 `VUE_APP_OA_ENABLED`（若有） |
| `mock/data/menus.js` | 删 4000–4005 及角色授权 |
| `package.json` | 删 `bpmn-js` 后 `npm install` |

自检：

```bash
rg -n 'bpmn-js|@/api/oa|views/admin/oa|oaBpmnBrand|oa-theme' src mock package.json
```

## B.2 后端删除

```bash
rm -rf src/main/java/com/geekplus/oa
rm -rf src/main/resources/mybatis/oa
rm -f src/main/resources/db/migration_oa_*.sql
rm -f src/main/java/com/geekplus/framework/jwtshiro/OaFileAccessFilter.java
rm -f src/main/resources/db/migration_flowable_*.sql   # 若仅 OA 用
# 若曾按方式 A：去掉 spring.factories 中 EPP，或删整个 factories 中对应行
```

| 文件 | 操作 |
|------|------|
| `GeekPlusBlogApplication` | `@MapperScan` 去掉 oa；无 Flowable 后去掉 EventRegistry/IDM `exclude` |
| `ShiroConfig` | 去掉 OA 附件 Filter 与 `/oa/files/**` |
| `application-*.yml` | 删 `flowable:`、`oa:`、`geekplus.modules.oa`；按需保留 `geekplus.signature` |
| `pom.xml` | 删 Flowable 依赖 |

库表（可选）：`DROP` OA 业务表与 `ACT_*`；禁用/删除菜单约 `540–549`。

自检：

```bash
rg -n 'com\.geekplus\.oa|flowable|OaFileAccessFilter|/oa/' src pom.xml
```

## B.3 物理删除 · 验收

- `build` / 启动成功；无 OA 菜单；`/oa/**` 404  
- 全局无 `bpmn-js` / `com.geekplus.oa` 业务残留  
- 再启用只能 git 回滚  

---

## 对照小结

| 维度 | 方式 A 逻辑去掉 | 方式 B 物理删除 |
|------|-----------------|-----------------|
| 改什么 | 配置 + 少量接线（开关） | 删文件 / 依赖 / SQL |
| 不建表 / 不启引擎 | 靠 `modules.oa=false` + 排除 Flowable 自动配置 | 无依赖即无引擎 |
| 业务不用 | 菜单过滤 + 无 Bean | 无代码 |
| 维护成本 | 仓内仍有 OA，偶发合并冲突 | 干净，但恢复成本高 |
